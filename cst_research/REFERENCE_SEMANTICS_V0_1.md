# Reference Semantics: Beyond Absolute vs Delta\n\nThe same action vector can have different executable meaning depending on who owns the reference state.\n\nImplemented reference kinds:\n- ABSOLUTE: action is the goal;\n- CURRENT_STATE: each step is relative to measured physical state at that step (ManiSkill pd_joint_delta_pos-style semantics);\n- CHUNK_ANCHOR: every action in a predicted chunk references one frozen state captured when the chunk was produced (LeRobot relative-action semantics);\n- PREVIOUS_COMMAND: sequential deltas accumulate from the previous decoded command;\n- CONTROLLER_TARGET: deltas reference controller-owned target state, which can differ from both measured state and previous command.\n\nThis distinction produces a concrete result: copying the numeric chunk [1,2,3] from CHUNK_ANCHOR semantics into PREVIOUS_COMMAND semantics changes absolute goals from [11,12,13] to [11,13,16]. Shape, units and numeric ranges are identical; only reference ownership changed.\n\nCST therefore treats reference ownership as part of the executable action type. Migration is decode-to-goal then re-encode-under-target-reference, not tensor copying.\n\nNovelty boundary: LeRobot already implements relative-to-current-chunk-anchor processing, and sequential delta representations are established. The contribution here is the unified executable-contract type used to compile and certify migrations across stacks, not either representation itself.
