## Why this follow-up exists

The earlier direct semantic-fidelity run used request sequences generated by
each implementation's own replay. That established the mechanism but left a
causal objection: trajectory divergence could change the request distribution.

This follow-up freezes two immutable request corpora and evaluates **all four
implementations on exactly the same inputs within each corpus**:

1. one corpus generated by current main;
2. one corpus generated by the composed repair.

Within a corpus the compared cells receive the same delta poses, episode IDs,
within-episode ordering, and controller normalization context.

## Interpretation

This provides a concrete embodied-software example of **semantic epistasis**:

- two locally inconsistent semantic boundaries substantially compensate;
- current end-to-end behavior can therefore look healthy even though the two
  individual contracts are wrong;
- correcting either boundary alone removes one side of the compensation and
  exposes the remaining fault;
- correcting both boundaries restores the intended converter/controller
  rotation semantics.

This falsifies the deployment implication:

```text
local repair correctness => safe singleton activation
```

The appropriate authorization unit is the interaction-certified repair bundle,
not each local patch independently.

## Important separation from task-level replay

The paired semantic metric and replay success are different gates.

Public official-demo replay has shown approximately:

- current main: 9/10
- converter-only: 1/10
- controller-only: 0/10
- composed: 8/10

Therefore the composed repair currently passes the direct semantic-fidelity
interaction gate but has **not** established strict execution-domain
non-regression relative to main.

Semantic correctness is necessary evidence for the representation contract; it
is not by itself authorization for deployment.
